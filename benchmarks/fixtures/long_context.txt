Engineering notes on running large language models locally on a laptop with unified memory. The machine in question has a single pool of memory shared by the CPU and the GPU, so there is no separate video memory to fill and no PCIe bus to cross when the GPU reads a weight. Decode speed for a resident model is governed almost entirely by how many bytes of weights must be streamed from memory for each generated token, divided by the sustained memory bandwidth, which on this class of chip is a few hundred gigabytes per second in theory and closer to forty gigabytes per second in practice for quantized matrix-vector work. Prefill is different: it is compute bound, because each weight that is loaded is reused across many prompt tokens at once, so prefill throughput scales with the GPU's arithmetic rate rather than with bandwidth. A mixture-of-experts model reads only the experts that the router selects for each token, which is why a thirty billion parameter model with three billion active parameters can decode faster than a dense eight billion parameter model. The external solid state drive that stores the model files is the slowest link in the system. Measured cold sequential reads reach roughly one gigabyte per second over the USB enclosure, and small random reads of sixty-four kilobytes fall to about three hundred megabytes per second. That is forty times slower than reading the same bytes from memory, so any design that streams weights from the drive during generation is limited by the drive, not by the chip. The single most important constraint on loading weights from an external SSD is therefore its bandwidth: a model must be fully resident in memory before generation begins, and choosing a quantization that fits in memory beats any scheme that pages experts in from the drive on demand. Swap makes this worse rather than better, because swap lives on the internal disk and a model that spills into swap stalls the whole machine. The memory guard refuses to load a model when the projected peak exceeds the memory that is available right now plus the swap headroom on the internal disk. Long conversations grow the key-value cache linearly with the number of tokens; for a model with forty-eight layers and four key-value heads of width one hundred twenty-eight, each token costs about one hundred kilobytes in half precision, so thirty-two thousand tokens of context cost about three gigabytes. Quantizing the cache to eight bits halves that cost with little quality loss, and four-bit caches halve it again at a measurable cost in accuracy on retrieval tasks. Reusing the cache across turns of the same conversation avoids recomputing the shared prefix, which is the dominant cost of time to first token in agent loops where every turn resends the whole history. Speculative decoding trades extra verification compute for fewer sequential steps; it pays off when the proposals are usually right, as in code edits that copy most of a file, and it loses when proposals are usually wrong, because every rejected proposal still costs a forward pass over the proposed tokens.
