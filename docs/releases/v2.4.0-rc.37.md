# esh 2.4.0-rc.37: release notes

**Pre-release candidate.**
- **Previous tag:** `v2.4.0-rc.36` (2026-10-13). Its release job failed only because `VERSION` at the tagged commit still read `2.4.0-rc.35`, so the last *published* pre-release is rc.35.
- **Last stable release:** `v2.3.0`. 2.4.0 has not shipped stable; this RC continues that line.
- **Stable 2.4.0** is a separate decision after this RC is dogfooded.

## Highlights
- **Managed SDK runtime** (#31). `lifecycle: .managed()` gives SDK apps the same model pool, load gate, KV-growth guard and memory-pressure handling as `esh serve`: warm models, bounded concurrency, idle and LRU eviction. It also fixes the embedded GGUF per-call native memory leak. `.oneShot` remains the default and is unchanged for existing callers.
- **Model readiness and options API** (#23, #30). `textModelReadiness(_:)`, `modelOptions(for:)` and `runtimeStatus()` drive model pickers and diagnostics without loading a model.
- **Conversation-aware MLX prefix caching** (#39). Concurrent conversations on one MLX model each keep their own prefix cache. In #38's experiment: later-turn hits under concurrency went from 25% to **100%**, freshly prefilled tokens dropped 91%, wall time dropped 39%, and concurrent text became identical to serial.
- **GGUF chat-template parity** (#44). The embedded GGUF path renders the model's own Jinja chat template, as llama-server (`--jinja`), mlx-lm and transformers do. The SDK and `esh serve` now send identical prompt tokens.
- **Inference hardening** (#24, #25, #27):
  - live MLX prefix caching by default in the persistent worker;
  - token-exact snapshot reuse with a disk guard;
  - opt-in speculative decoding;
  - the load gate on every path;
  - KV-cache accounting;
  - crash-safe temp files.
- **Speech** (#22). mlx_audio STT and TTS compat engines are selectable; Apple's native speech stays the default.

## Compatibility and migration
**Source-compatible.** No public API was removed or changed incompatibly. New, all optional:
- `GenerationConfig.prefixCacheKey`;
- OpenAI `prompt_cache_key` on `/v1/chat/completions` and `/v1/responses`;
- `EshRuntimeLifecycle.managed(EshManagedLifecycleConfiguration)`;
- `runtimeStatus()`, `textModelReadiness(_:)`, `modelOptions(for:)`, `prewarm(modelID:)`, `unload(modelID:)`, `unloadIdleRuntimes()` and `shutdown()`.

**Behavior changes to review before upgrading:**
1. **Embedded GGUF prompts follow the model's own chat template** (#44). For Qwen2.5 GGUFs this inserts the model's default system prompt (`You are Qwen, created by Alibaba Cloud. You are a helpful assistant.`) when a conversation has no system message, so embedded GGUF output differs from rc.36. Send an explicit system message to control this; both GGUF paths then render it identically. If a template can't be rendered, esh falls back to the previous formatter.
2. **MLX live prefix-cache slots: up to 8 conversations** (#39; was 2). This is still bounded by the live-cache byte budget (`ESH_MLX_LIVE_PREFIX_MAX_BYTES`, default min(25% RAM, 8 GiB)), counted in the pool's memory budget, and released under pressure. Set `ESH_MLX_LIVE_PREFIX_SLOTS=2` for the old cap.
3. **`EshLlamaCpp` gains a package dependency: swift-jinja** (#44).
   - **Requirement and resolution:** `from: "2.4.2"`, swift-transformers' own requirement. It resolves to 2.5.1, the version already pinned in `Package.resolved`, so the file is unchanged.
   - **Footprint:** it brings only swift-collections, with no swift-syntax. Its platform floors (iOS 16, macOS 13) are below esh's (iOS 17, macOS 14).
   - **Binary size:** measured on `Examples/EshIOSProbe` (iOS arm64, Release), **+2.17 MB executable (9.88 → 12.05 MB, +22%)**.
   - `EshCore` and `EshRuntime` remain free of external dependencies.
4. **`esh serve` security model** (#43). It is single-tenant and assumes trusted clients. Prompt-cache keys (explicit or derived) are performance hints, not security identities; reuse is exact-token-prefix only, so content can't cross conversations. Run one server per trust domain. Tenant isolation is tracked in #42.

**Studio:** pin to `v2.4.0-rc.37`. See `docs/integration/esh-studio-sdk-handoff.md`; to keep a stable cache identity per chat, set `GenerationConfig.prefixCacheKey` to the chat id.

## Known limitations
- **MLX numerics:** prefix reuse vs full prefill can flip greedy near-ties. On Qwen3-0.6B the one-shot SDK path, which re-prefills every call, diverged from the managed path at a 0.5-logit margin. Text equality across reuse paths is not guaranteed (#38).
- **MLX concurrency:**
  - More concurrent conversations than slots thrash LRU (correct, slower).
  - The shared per-runtime snapshot fallback still thrashes under concurrency (#40).
  - Conversations with an identical opening and no `prompt_cache_key` share one cache identity.
- **Security:** no tenant isolation in `esh serve`, and reuse timing is observable across clients (#42).
- **GGUF:**
  - Embedded (llama.cpp `4a89937`) and server (b8660) builds matched in validation, but numerics can differ on other models or longer outputs.
  - `enable_thinking` and tools aren't passed into the embedded template context.
- **Platform and coverage:**
  - iOS is build-verified, not device-measured.
  - Real system memory-pressure events aren't exercised (the reactions are unit-tested).
  - MLX-to-MLX model switching wasn't run live (no second small MLX model installed).
